3. Storage of Plaintext Master Key in Secure Storage
   Severity: Low to Medium (Tradeoff for Biometrics) Location: gateway_controller.dart, master_key_page.dart Issue: To support biometric unlock, the raw, plaintext masterKey is stored in flutter_secure_storage. While iOS Keychain and Android Keystore provide strong hardware-backed security, a highly motivated attacker with a rooted/jailbroken device could potentially extract this plaintext password. Fix: Given that the app's architecture requires the master key to dynamically decrypt cloud data on the fly, storing a secret on the device is unavoidable for biometric unlocks. Storing the derived SecureKey bytes instead of the plaintext masterKey would be marginally better, as an extracted key couldn't be used across other accounts if the user re-used their master password elsewhere. However, keeping the plaintext in Keystore is a standard tradeoff for offline biometric convenience in many password managers.

4. Master Key Verification via Self-Encryption
   Severity: Informational Location: encryption_local.dart -> encryptMasterKeyForSync() Issue: The m_key collection stores the masterKey encrypted by a key derived from itself. To verify the master key on login, the app attempts to decrypt this blob. While functionally correct, a more standard approach for pure verification is storing a strong one-way hash (Argon2) of the master key. Note: Because the current method's security relies entirely on the strength of the deriveKey function, fixing Issue #1 (implementing Argon2id) automatically secures this mechanism as well.
